# 桌面更新签名与发布（SEC-01，2026-11-27）

当前默认 **禁用应用内自动下载与执行**：`package.json` 的 `okplay.updatePublicKey` 为空。客户端不查询更新源，也不显示更新按钮。保留的 HTTPS 地址不代表已启用更新。旧版无签名更新 JSON 不再受信。

本次仅修源码，未生成生产密钥、重打包、覆盖已有发行物或发布更新。已经安装的旧客户端不会因本地源码修改而自动获得保护；需通过受控渠道发放新构建。

## 启用前提

1. 在受控离线发布环境持有 Ed25519 私钥，私钥与更新服务器、代码仓库、打包产物隔离。本项目不自动生成生产私钥。
2. 构建前，把对应 **公钥** 的完整 SPKI PEM 字符串写入 `package.json` 的 `okplay.updatePublicKey`。这里只允许公钥，严禁放私钥；JSON 字符串中的换行需转义。
3. 固定 `okplay.updateFeed` 为受控 HTTPS 发布地址。正式安装包忽略 `OKPLAY_UPDATE_URL` 环境覆盖；源码调试仅在已配置公钥时允许替换源，仍必须通过相同验签。
4. 在干净 Windows 验证新构建及签名更新，再人工发布。没有准备好固定公钥时，保持默认禁用状态，通过已确认的官方渠道人工安装。

## 清单协议

清单字段为 `schema: 1`、`version`、`url`、小写十六进制 `sha256`、Base64 `signature`。签名覆盖按此固定顺序序列化的 UTF-8 JSON：`schema`、`version`、`url`、`sha256`；`signature` 本身不在签名内容中。

算法为 Ed25519，不进行额外摘要。URL 必须是规范化的 HTTPS EXE 地址；版本号与下载 hash 均受签名保护。客户端只信构建中固定的公钥，清单不能附带新公钥来更换信任根。

下载前先验证发布签名；下载时限制大小并验证 SHA256；执行前重新验证清单签名并重新计算安装包 hash。下载/执行任何一步失败，都不能启动安装器。HTTPS 与 hash 不代替发布签名。

## 离线签名工具

先打包到受控输出目录，再显式调用：

```powershell
node tools/make-update-feed.cjs <发布目录> --key-file <离线Ed25519私钥文件路径>
node tools/verify-release.cjs <发布目录>
```

工具只读取明确指定的签名密钥，不把它复制到输出目录，不输出密钥内容。私钥必须与当前构建固定的公钥匹配；未指定私钥但已配置公钥时，工具失败。

公钥和私钥都未配置时，工具只生成 `{ "schema": 1, "enabled": false, "version": "当前版本" }` 的禁用清单，不附安装包 URL 或 hash。这让现有打包脚本可以产出默认关闭自动更新的构建；不能据此宣称签名更新已启用。

已配置公钥的构建，请分开执行打包和离线签名步骤；不要把密钥塞入 npm 脚本、环境字符串或源码。验收工具核对归档公钥与构建配置一致，并校验签名、版本、包地址及 hash。

## 验证与密钥轮换

`node --test test/*.test.cjs` 使用仅存于测试内存或临时目录的合成密钥。`electron.exe . --qa-update-security` 使用独立临时会话与动态合成签名，验证拒绝无签名/错签名、有效签名下载和执行前校验、模拟安装重试与关闭；不会访问生产或执行真实安装器。正式包明确拒绝 QA 参数，测试夹具不进入发行包。

更换发布公钥必须通过受信旧密钥签发的过渡构建或受控渠道人工重装。不得从更新 JSON 或用户环境变量直接接受新的信任根。当前实现不提供在线密钥轮换/撤销服务。
